# 东软电动汽车充电桩应用管理平台 — 开发计划书

## 一、目标形态

拆分为 **两个 Qt 程序 + 一个 Web 大屏**：

| 程序 | 说明 | 技术 |
| ---- | ---- | ---- |
| 服务端 ChargingServer | 面向管理员的后台（管理端 6 大功能）+ TCP 服务端（处理客户端业务）+ 数据库唯一持有者 + 定时导出大屏数据 | Qt Widgets + QSqlite + QTcpServer/QThread |
| 用户客户端 ChargingClient | 面向车主的用户端（4 大功能），不直接访问数据库，所有业务经 Socket 请求服务端 | Qt Widgets + QTcpSocket |
| Web 大屏 | ECharts 可视化，读取服务端定时导出的 data.json | HTML + ECharts（本地化，浏览器打开） |

充电站/电桩分布数据采用**固定种子数据**（启动时只在表为空时写入，每次运行完全一致）；不接腾讯地图真实 API，定位/距离/导航全部用模拟数据实现。

## 二、目标架构

```
code/
├── ChargingPlatform.pro        # subdirs: server + client
├── common/                     # 双方共享: common.pri + protocol.h(消息定义) + types.h(枚举/DTO) + JsonHelper
├── server/                     # 服务端: AdminLoginDialog, AdminMainWindow, pages/*, TcpServer(多线程),
│                               #   OrderSimulator(充电计时), DatabaseManager/Dao, DataExporter(大屏JSON), Predictor(负荷预测)
├── client/                     # 客户端: LoginDialog(手机号), UserMainWindow, pages/*, TcpClient(请求-响应+超时重连)
├── resources/                  # 共享 qss/qrc（沿用现有 login.qss/global.qss）
└── web/                        # index.html + echarts.min.js + data.json(服务端生成)
```

**通信协议**：TCP 长连接 + UTF-8 JSON 行分隔协议。消息类型：手机号登录、查用户/改资料/充值、查充电站列表/站内电桩、开始充电、查未完成订单、充电进度推送（服务端定时推）、订单结算、心跳。服务端收到请求→业务处理→写库→回 JSON 应答。

**多线程**：服务端每客户端连接一个工作线程（QThread，线程内独立 QSqlDatabase 连接）；充电进度用 QTimer 模拟器按桩功率累计电量。客户端 Socket 收发独立线程，UI 线程只做展示。

## 四、分阶段任务

### 阶段 0：工程拆分重构（约 1 次交付）
1. 写《开发计划书》Markdown 存入 docs/（本计划书正式化：含任务分解、里程碑、分工建议、风险）。
2. qmake 改为 subdirs 模板；common.pri 共享协议与类型；现有代码迁移：
   - DatabaseManager/管理端窗口与页面 → server/（管理员登录改为服务端本地校验，新建 AdminLoginDialog 复用现有样式）；
   - LoginDialog（手机号登录改为经 Socket 校验）、UserMainWindow 及页面 → client/；
   - 新增 client 端 TcpClient 封装（连接/请求-响应/超时/断线提示）与服务端 TcpServer 骨架。
3. protocol.h 定义全部消息类型与字段（含错误码），写成注释即协议文档。
- 验收：两个程序编译启动，客户端登录能经 Socket 校验（服务端在本机即可测试）。

### 阶段 1：服务端 + 管理端页面
1. 服务端多线程连接管理、心跳、断连清理；JSON 编解码与错误码统一。
2. 充电站管理：站列表（ID/站名/地址/经纬度/总桩数/在线率）、新增电站表单、点击行查看站内电桩明细。
3. 充电桩管理：电桩列表（编号/所属电站/类型/功率/状态/累计次数/时长）、选中执行"远程重启"（模拟：改状态+写操作日志+确认提示）。
4. 电桩状态：在用/闲置/故障数量与占比汇总。
5. 用户管理：用户列表、手机号模糊搜索、冻结/解冻（冻结后客户端登录被拦截）。
- 涉及文件：server/pages/ 五个页面 + server/dao/（StationDao/PileDao/UserDao/OrderDao）。
- 验收：所有数据来自数据库，增删改查立即生效，种子站点/电桩展示正常。

### 阶段 2：用户客户端全流程
1. 用户信息维护：灰色默认头像、本地图片更换头像、改昵称、余额充值（模拟支付，余额经服务端更新）。
2. 附近充电站查询：模拟 GPS（区域下拉/地址输入映射固定坐标），服务端计算距离并按近→远排序，站卡片显示站名/价格/总桩数/空闲数/距离，点击看桩详情。
3. 一键导航：自绘模拟地图页（站点散点+当前位置+驾车/步行路线折线+预计时长距离），不依赖外网。
4. 电动汽车充电：进入先查未完成订单（有则强制跳结算）→ 选空闲桩开始充电（服务端生成订单、桩置"在用"）→ 服务端 OrderSimulator 按功率定时累计电量电费并推送 → 结算（订单完结、扣余额、更新桩统计、桩置"闲置"）。
- 验收：双程序联调跑通完整业务闭环，余额/订单/桩状态数据一致。

### 阶段 3：销售业绩 + 大屏数据导出
1. 销售业绩页：今日/本月/总营收三大指标卡；QChart 近7日/近30日营收折线图，时间维度切换（.pro 启用 charts，VM 需 `apt install libqt5charts5-dev`）。
2. 服务端 DataExporter：QTimer 每 10 秒导出 web/data.json（营收指标、电桩状态分布、各站营收、近7日趋势）。
- 验收：图表数字与订单流水对得上；data.json 内容正确。

### 阶段 4：Web 可视化大屏
1. web/index.html：深色大屏布局 + 本地 ECharts：核心指标、电桩状态饼图、7日营收趋势线、各站营收柱状图、站点分布示意；fetch 轮询 data.json 自动刷新。
2. 附一键演示脚本（python3 -m http.server）与说明。
- 验收：浏览器打开大屏，客户端下一单后大屏指标随之变化。

### 阶段 5：机器学习负荷预测（简化）
1. 服务端 Predictor：按小时聚合近 30 天充电量 → 同小时近 7 日均值 × 星期系数 + 平滑，预测未来 24h 各站负荷/空闲桩数；纯 C++ 实现，不引入第三方库。
2. 结果并入 data.json（大屏显示预测曲线与高峰时段预警）；用户端附近充电站列表增加"预计空闲率"，优先推荐低负荷站。
- 验收：预测曲线随历史数据变化且平滑合理。

### 阶段 6：收尾
1. 错误处理机制：所有输入校验、SQL 事务（订单/结算）、Socket 断线提示与重连、统一错误码、qDebug 日志。
2. 数据安全：管理员密码改摘要存储（兼容首次种子）、SQL 全部预处理防注入、冻结风控生效。
3. 种子数据一致性确认（固定编号/坐标/价格，多次运行完全一致）。
4. 整理全流程测试清单（登录异常/充值/冻结/并发下单/断线/结算）供你虚拟机回归；更新 README。
