## 1. 项目概述

构建覆盖"用户端—服务端—数据端—大屏"全链条的充电桩管理平台，包含两个 Qt 程序与一个 Web 大屏：

| 子系统 | 形态 | 核心功能 |
| ---- | ---- | ---- |
| 用户客户端 ChargingClient | Qt 界面程序（模拟手机端） | 手机号免密登录、附近充电站查询、一键导航（模拟）、用户信息维护、电动汽车充电（预约—充电—计费—结算） |
| 服务端 ChargingServer | Qt 界面程序（管理后台）+ TCP 服务端 | 管理员登录、销售业绩、电桩状态、充电桩管理、充电站管理、用户管理；处理客户端业务请求；持有数据库 |
| 数据库 | SQLite（QSQLITE 驱动） | admin / user / station / pile / charge_order 五张表，仅服务端访问 |
| 大数据可视化大屏 | Web 页面（ECharts 本地化） | 营收指标、电桩状态分布、营收趋势、负荷预测曲线 |
| 加分项 | 服务端内置算法 | 充电负荷智能预测（简化版：同时段历史均值 + 星期系数 + 平滑） |

**关键技术落实**：
- Socket 通信：客户端所有业务请求（登录/查站/充电/订单）经 TCP 发送 JSON 到服务端处理并写库；
- 多线程：服务端每个客户端连接一个工作线程（QThread，线程内独立 QSqlDatabase 连接）；客户端 Socket 收发独立线程；
- 数据一致性：充电站/电桩分布采用固定种子数据（仅表为空时写入，多次运行完全一致）；定位/距离/导航全部模拟实现，不依赖外网。

## 2. 目标架构

```
code/
├── ChargingPlatform.pro        # subdirs: server + client
├── common/                     # 双端共享: common.pri + protocol.h(协议) + types.h(枚举/DTO)
├── server/                     # ChargingServer.pro
│   ├── DatabaseManager.*       # 数据库单例: 打开/建表/种子数据/登录查询(支持指定连接名)
│   ├── AdminLoginDialog.*      # 管理员登录(本机数据库校验)
│   ├── AdminMainWindow.*       # 管理后台(侧边导航+页面栈)
│   ├── pages/                  # 销售业绩/电桩状态/充电桩管理/充电站管理/用户管理
│   ├── network/                # TcpServer(每连接一线程) + ClientHandler(单连接业务处理)
│   └── (阶段3+) sim/OrderSimulator, DataExporter, Predictor
├── client/                     # ChargingClient.pro (不依赖 sql 模块)
│   ├── LoginDialog.*           # 手机号登录(经 Socket 校验, 首次自动注册)
│   ├── UserMainWindow.* / pages/  # 附近充电站/一键导航/用户信息/电动汽车充电
│   └── network/TcpClient.*     # 请求-响应封装(独立线程+超时) + 推送分发
├── resources/                  # 共享 qss / qrc
└── web/                        # index.html + echarts.min.js + data.json(服务端导出)
```

**通信协议**：TCP 长连接，UTF-8 单行 JSON，以 `\n` 分帧。请求/应答回显相同 `type`，统一 `ok` / `error` 字段；`type>=100` 为服务端推送（充电进度）。全部消息定义见 `common/protocol.h`。默认地址 `127.0.0.1:9527`，可用环境变量 `CHARGING_SERVER_HOST` / `CHARGING_SERVER_PORT` 覆盖。

## 4. 各阶段任务分解（WBS）

### 阶段 0：工程拆分重构
1. 计划书文档化（本文档）；
2. 根工程改 subdirs，抽离 common.pri 共享协议与类型；
3. 服务端：迁移 DatabaseManager / 管理端窗口与页面，新建 AdminLoginDialog；
4. 客户端：迁移用户端窗口与页面，LoginDialog 改为 Socket 登录；
5. 实现 TcpServer（每连接一线程）+ ClientHandler（登录/心跳）+ TcpClient（请求-响应+超时+推送分发）；
6. protocol.h 定义全部消息类型与字段。

### 阶段 1：服务端 + 管理端页面
1. 多线程连接管理完善：心跳、异常断连清理、请求日志；
2. Dao 层：StationDao / PileDao / UserDao / OrderDao；
3. 充电站管理：列表（在线率统计）、新增电站、点击行查看站内电桩明细；
4. 充电桩管理：列表（联表查询）、远程重启（模拟：改状态+操作日志）；
5. 电桩状态：在用/闲置/故障数量与占比；
6. 用户管理：列表、手机号模糊搜索、冻结/解冻（冻结后客户端登录被拦截）。

### 阶段 2：用户客户端全流程
1. 用户信息维护：默认灰色头像、本地图更换、改昵称、余额充值（均经 Socket）；
2. 附近充电站：模拟 GPS（区域下拉/地址输入→固定坐标），服务端计算距离排序，站卡片（站名/价格/总桩数/空闲数/距离），点击看桩详情；
3. 一键导航：自绘模拟地图（站点散点+当前位置+驾车/步行路线+预计时长距离）；
4. 充电流程：未完成订单强制结算检查 → 选空闲桩下单（桩置"在用"）→ 服务端 OrderSimulator 按功率定时累计电量电费并推送 → 结算（扣余额/更新桩统计/桩置"闲置"）。

### 阶段 3：销售业绩 + 大屏导出
1. 今日/本月/总营收指标卡；近 7 日/近 30 日营收折线图（QChart，需 `apt install libqt5charts5-dev`）；
2. DataExporter：每 10 秒导出 web/data.json（营收/电桩状态分布/各站营收/趋势）。

### 阶段 4：Web 大屏
1. 深色大屏 + 本地 ECharts：核心指标、状态饼图、趋势线、各站柱状图；fetch 轮询 data.json；
2. 一键演示脚本（python3 -m http.server）。

### 阶段 5：负荷预测（简化）
1. 按小时聚合近 30 天充电量 → 同小时近 7 日均值 × 星期系数 + 平滑 → 未来 24h 预测；纯 C++；
2. 大屏预测曲线与高峰预警；用户端列表显示"预计空闲率"并优先推荐低负荷站。

### 阶段 6：收尾
1. 错误处理：输入校验、SQL 事务、断线提示重连、统一错误码、日志；
2. 数据安全：管理员密码摘要存储、SQL 全预处理防注入、冻结风控；
3. 种子数据一致性确认；
4. 全流程测试清单 + README 收尾。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
| ---- | ---- | ---- |
| Qt Charts 组件未安装 | 编译失败 | 提前安装 libqt5charts5-dev；找不到包则降级自绘折线图 |
| 多线程数据库访问冲突 | 数据异常/崩溃 | 每线程独立 QSqlDatabase 连接 + busy_timeout + 写事务 |
| 虚拟机性能不足 | 图表/大屏卡顿 | 大屏轮询间隔可调，图表控制在 30 个数据点内 |
| 双程序联调问题难定位 | 排查慢 | 协议消息统一 qDebug 日志（类型+来源+耗时） |
| 中文乱码 | 界面异常 | 源码统一 UTF-8，Qt Creator 默认编码检查 |
