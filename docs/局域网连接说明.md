# 两台电脑通过局域网连接

## 服务端电脑

1. 打开重新编译后的 `ChargingServer`，完成管理员登录。
2. 在管理后台顶部查看“客户端连接地址”，例如 `192.168.1.100:9527`。
3. 冒号前是 IP，冒号后是端口。可以点击“复制地址”。有多个网卡时，下拉列表会列出各网卡地址及名称，选择与客户端处于同一局域网的地址。
4. 网卡地址每 10 秒刷新，也可点击“刷新”。显示“未发现局域网 IP”时，先连接 Wi-Fi 或网线；`127.0.0.1` 只用于本机测试。
5. 如果显示“客户端服务未启动”，表示监听失败，需要先解决端口占用等问题，不能把大屏的 8080 端口作为客户端连接端口。

## 客户端电脑

1. 打开重新编译后的 `ChargingClient`。
2. 在登录页“服务器 IP 与端口”填写服务端显示的信息，例如 IP 填 `192.168.1.100`，端口填 `9527`。
3. 点击“连接服务器”。显示“已连接……，可以登录”后输入手机号，点击“登录 / 注册”。也可以填好地址和手机号后直接登录，程序会先检查连接。
4. 成功验证连接后会自动保存 IP 和端口，下次启动不需要重复输入。连接失败不会覆盖上一次保存的地址。
5. 地址改变后重新连接即可；程序会关闭旧连接，避免仍连着旧服务器。手机号在登录失败时会保留。

## 连接失败时

- 确认服务端正在运行，双方连接到可互相访问的同一局域网。访客 Wi-Fi 或开启设备隔离的网络可能无法互通。
- 检查 IP 和端口是否与服务端面板一致；另一台电脑不能填写 `127.0.0.1`。
- 在服务端操作系统的防火墙设置中允许 ChargingServer 使用专用网络，或允许面板显示的 TCP 端口。
- macOS 需要在“系统设置 → 隐私与安全性 → 本地网络”中允许 ChargingServer/Qt Creator；防火墙开启时也要允许该程序接收入站连接。
- `连接被拒绝` 表示目标电脑可达，但 9527 端口没有监听或被防火墙明确拒绝；`连接超时` 通常表示 IP 填错、系统权限拦截，或路由器/校园网开启了终端隔离。
- “连到同一个 Wi-Fi 名称”不一定代表设备可以互访。校园网、公司网和访客网络常开启终端隔离，可先改用允许设备互访的家用路由器或电脑热点验证。
- 如果服务端在 VMware 虚拟机内，跨电脑连接时优先在 VMware 的虚拟机设置中选择桥接网络，并使用虚拟机内服务端面板显示的局域网 IP。NAT 模式通常需要额外配置端口转发。
- 局域网 TCP 连接固定直连，不经过系统代理；地图和路线请求仍保持原来的代理行为。

## 配置兼容

没有保存过地址时，客户端以 `CHARGING_SERVER_HOST`、`CHARGING_SERVER_PORT` 为初始默认值，否则默认 `127.0.0.1:9527`。登录页输入优先；成功连接后保存的值用于下次启动。服务端仍使用 `CHARGING_SERVER_PORT` 或默认 9527，面板展示实际监听端口。非法的环境变量端口回退为 9527。

## 验证范围

自动化测试使用本机临时端口和临时配置目录，覆盖连接切换、失败重试、超时取消、代理绕过、登录页校验、地址保存和服务端无应答。服务端集成测试使用临时数据库，验证真实 TCP 登录、实际端口显示、复制地址、监听关闭状态及原有充电结算流程。跨两台物理电脑的连通性需要在实际局域网中验证。
