# 全流程测试清单（阶段6 交付）

虚拟机（Ubuntu 22.04 + Qt 5.15/Qt6）中按序执行。建议服务端从 Qt Creator 运行，
客户端另开一个终端从构建目录运行，方便同时观察两端日志。

## 0. 准备

- [ ] 根工程 `ChargingPlatform.pro` 重新 qmake + 构建通过（server / client 两个可执行文件）
- [ ] Qt Charts 依赖（**可选**）：Qt5 `sudo apt install libqt5charts5-dev`；Qt6 `sudo apt install libqt6charts6-dev`。已实现自动降级：安装了用 QChart 折线图，未安装时销售业绩页自动改用自绘折线图，两种情况下工程均可编译通过
- [ ] Qt WebEngine 依赖（**真实地图需要**）：Qt5 `sudo apt install qtwebengine5-dev`；Qt6 `sudo apt install qt6-webengine-dev`；重新 qmake 后构建日志不再出现“导航页将使用降级画布”
- [ ] 如需全新数据库：删除 test.db 后首次运行会自动重建表与种子数据

## 1. 服务端（ChargingServer）

- [ ] 启动服务端 → 管理员登录 admin / 123456 成功
- [ ] 错误密码 → 弹"用户名或密码错误"，密码清空、账号保留
- [ ] 登录后状态栏显示：数据库路径、"服务端口 9527 监听中"、大屏数据路径
- [ ] 销售业绩：三张指标卡显示数字（新库为 0.00）；近7日/近30日切换图表正常
- [ ] 电桩状态：在用/闲置/故障数量与种子一致（88 台：在用 15、故障 12、闲置 61），占比正确
- [ ] 充电桩管理：列表 7 列完整；选中"在用"的桩点远程重启 → 拒绝；选中"故障"桩 → 重启成功变闲置
- [ ] 充电站管理：12 个种子站；点击行右侧显示站内电桩明细；新增电站（如"测试站"2 桩）→ 列表出现、电桩编号顺延
- [ ] 用户管理：搜索手机号片段能过滤；冻结某用户 → 该用户客户端再登录被拦截；解冻后恢复

## 2. 客户端（ChargingClient）

- [ ] 不启动服务端直接登录 → 提示"无法连接服务器"
- [ ] 启动服务端后，输入非 11 位手机号 → 本地拦截；正确手机号 → 登录/自动注册成功
- [ ] 附近充电站：切换区域或输入内置地标 → 距离变化、按近→远排序；双击站点 → 电桩详情正确；无腾讯 Key 也能使用
- [ ] 一键导航：选择起点和终点 → 真实道路底图显示当前位置与充电站，点击站点弹出价格和空闲桩信息
- [ ] 一键导航：驾车/步行“路线预览” → 路线折线、道路距离和预计时长显示；连续点击受 1 秒间隔限制
- [ ] 一键导航：点击“开始导航” → 默认浏览器打开高德路线页面，起终点和驾车/步行方式正确
- [ ] 一键导航异常：断网或开放路线服务超时 → 10 秒内提示预览不可用，站点列表和高德按钮不崩溃
- [ ] 用户信息：改昵称保存后重新进入页面仍为新昵称；更换头像生效；充值 50 元余额实时增加

## 3. 充电全流程（核心闭环）

- [ ] 充电页双击空闲电桩 → 进入充电视图，进度（电量/费用/时长）每 3 秒刷新
- [ ] 服务端日志出现"开始充电"；管理端充电桩管理中该桩变"在用"
- [ ] 充电中重新进入充电页 → 弹"您有未完成的充电订单，请先结算"并回到充电视图
- [ ] 余额不足时结算 → 拒绝并提示充值；充值后结算成功 → 显示电量/金额/余额
- [ ] 结算后：管理端该桩变"闲置"、累计次数+1、销售业绩今日营收增加、订单状态已完成
- [ ] 充电中强杀客户端再重新登录 → 订单仍在，可继续结算（进度计时器兜底）

## 4. 大数据可视化大屏

- [ ] 服务端运行 10 秒内生成 web/data.json
- [ ] `cd code/web && bash start.sh`（或 `python3 -m http.server 8080`）→ 浏览器打开 127.0.0.1:8080
- [ ] 四块图表渲染正常，完成一笔充电结算后 10 秒内指标/趋势自动变化
- [ ] 负荷预测曲线平滑，高峰时段与曲线峰值一致

## 5. 异常与安全

- [ ] 手机号含字母 → 无法输入（输入限制）
- [ ] 管理员密码库中为加盐 SHA-256 摘要（sqlite3 查看 admin 表确认，非明文/非旧 MD5）
- [ ] SQL 全部预处理参数绑定（代码走查）
- [ ] 服务端重启后：客户端重连提示/重新登录正常，历史数据完整
