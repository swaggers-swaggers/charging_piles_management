# Web 大屏智能化升级实施方案

## 1. 项目目标与改造边界

### 1.1 建设目标

将现有 Web 大屏从“基础经营数据展示页”升级为“充电运营智能决策中心”，面向运营决策者集中展示：

1. 业务实时健康度：营收、订单、充电量、设备利用率、故障率、用户规模。
2. 机器学习智能分析：1/6/24 小时负荷预测、空闲桩预测、充电时长预测、故障风险诊断。
3. 智能决策建议：站点推荐、削峰填谷、运维工单优先级、异常风险提醒。
4. Hadoop 大数据链路：采集、存储、清洗、分析、建模、结果服务和可视化全流程可展示、可追溯。

### 1.2 改造边界

- 保留现有 Qt 客户端、Qt 管理后台、TCP 协议和 SQLite 业务库，不改变原有业务流程。
- 保留当前大屏的浅色绿色视觉基因：白底、深绿主色、浅绿辅助色、金色重点指标、红色告警。
- Web 大屏独立升级；Hadoop 和机器学习代码放入新目录，通过只读抽取业务数据和输出 JSON 结果接入。
- 原有 `/data.json` 继续可用。Hadoop 或模型服务不可用时，大屏自动降级到当前实时聚合数据和演示数据，保证答辩稳定。

## 2. 当前项目基础与主要缺口

### 2.1 已有能力

- `code/web/index.html`：原生 HTML/CSS/JavaScript + 本地 ECharts，大约每 5 秒刷新。
- `code/server/HttpServer.cpp`：提供静态页面和 `/data.json`。
- `code/server/DataExporter.cpp`：聚合营收、7 日趋势、电桩状态、站点营收和 24 小时预测。
- `code/server/Predictor.cpp`：基于近 14 天分时平均、工作日/周末系数和滑动平均生成 24 小时负荷曲线。

### 2.2 当前缺口

- 只有单页 4 指标、4 图表，缺少订单、充电量、利用率、故障、用户、区域等决策指标。
- 当前预测属于规则增强的统计预测，不是经过训练、验证、部署的完整机器学习模型。
- 数据中暂缺天气、节假日、实时设备遥测和标准故障事件，需要新增模拟采集或外部样例数据。
- 未建立 HDFS/Hive 数据分层、Spark 计算任务、模型评估、版本管理和推理结果输出链路。
- 缺少预测置信区间、模型准确率、影响因素和决策建议，不能说明“为什么这样预测、应该怎么做”。

## 3. 大屏功能大纲预览

建议采用“一块大屏、四个主题视图、顶部无刷新切换”的结构，避免在一页堆放过多图表。

### 3.1 视图一：运营总览（默认首页）

**核心指标卡**

- 今日营收、今日订单、今日充电量、在线充电桩数。
- 设备利用率、故障率、平均客单价、累计服务用户。
- 指标显示环比、同比或相对昨日变化，并使用红/绿状态标识。

**核心图表**

- 近 24 小时充电负荷与订单双轴趋势。
- 充电桩状态环图：空闲、充电中、预约、离线、故障。
- 各站点运营排行：营收、充电量、利用率可切换。
- 城市/区域站点分布图：站点圆点大小表示负荷，颜色表示健康度。
- 实时事件流：订单开始、订单结束、故障、恢复、负荷预警。

### 3.2 视图二：AI 智能预测

**充电负荷智能预测**

- 支持全网/单站点筛选，以及未来 1 小时、6 小时、24 小时切换。
- 同图显示历史真实值、预测值、P10-P90 置信区间和容量警戒线。
- 输出预测负荷、预计空闲桩数、高峰时段、拥堵等级。
- 展示 MAE、RMSE、MAPE、模型版本、训练时间和数据时间范围。

**充电时间预测**

- 输入或选择：站点、电桩、车型/电池容量、当前电量、目标电量、环境温度。
- 输出：预计充电分钟数、预计完成时刻、费用区间、可信度。
- 图表展示充电功率随时间变化和预计 SOC 曲线。

**智能站点推荐**

- 综合距离、预测空闲率、预计排队时间、价格和故障风险生成推荐分。
- 展示 Top 5 推荐站点，并给出可解释原因，例如“预计空闲 12 桩、低谷电价、拥堵风险低”。

### 3.3 视图三：智能运维与风控

**设备健康与故障诊断**

- 展示健康、关注、高风险、故障设备数量。
- 故障风险 Top 10：桩编号、站点、风险概率、预计故障类型、主要影响特征。
- 电压、电流、温度、功率、离线时长、启动失败率趋势。
- 运维建议：立即检修、24 小时内巡检、继续观察，并形成优先级。

**智能风控**

- 异常订单、异常高频充电、金额/电量不匹配、账户异常操作。
- 风险等级和异常原因展示，不直接自动封禁用户，仅向运营人员提供审核依据。

### 3.4 视图四：能源与大数据驾驶舱

**绿色能源指标**

- 累计充电量、估算碳减排量、峰时负荷占比、谷时充电占比。
- 峰谷电价收益、削峰潜力和站点能效排行。

**Hadoop 数据链路监控**

- 今日采集记录数、HDFS 存储量、Hive 分区数、Spark 任务成功率、最新数据延迟。
- ODS→DWD→DWS→ADS 数据流状态，以流程图或桑基图展示。
- 数据质量分：完整性、及时性、一致性、异常率。

## 4. 推荐的核心亮点

除题目要求外，建议重点完成以下 5 项。前三项是答辩时最有辨识度的“必做亮点”。

### 4.1 AI 决策建议中心（必做）

不仅展示预测曲线，还将预测翻译成可执行建议：

- “18:00-20:00 预计负荷超过 85%，建议提前开放备用桩并安排值守。”
- “A 站预计排队 23 分钟，建议用户前往 1.8 km 外的 B 站。”
- “7 号桩未来 24 小时故障风险 82%，建议优先检查枪温与通信模块。”

### 4.2 预测可解释性（必做）

通过横向条形图展示模型主要影响因素，例如小时、星期、温度、降雨、节假日、前 1 小时负荷、前 24 小时负荷。这样能回答“模型为什么得出这个结果”。

### 4.3 运营 What-if 模拟器（必做）

运营人员可调整“电价 ±20%”“新增可用桩数”“天气变化”“节假日”等参数，大屏即时模拟负荷、排队时间、营收和利用率变化。该功能只在浏览器或独立分析服务中模拟，不写回业务数据库。

### 4.4 碳减排与削峰填谷看板（建议）

将充电量换算为燃油替代和碳减排估算值，展示谷时引导前后的峰谷差变化。页面必须标注估算口径，避免将估算值当作权威统计。

### 4.5 数据质量与模型健康监控（建议）

展示数据延迟、缺失率、异常值比例、模型版本、最近一次训练、预测误差漂移。这能体现系统不是一次性“跑模型”，而是具备持续运营能力。

## 5. Hadoop 大数据技术方案

### 5.1 总体架构

```text
SQLite 业务库     设备遥测模拟器     天气/节假日数据
      \                |                 /
       +------ Python/Kafka 数据采集 ----+
                         |
                         v
                    HDFS / ODS
                         |
                   Spark 清洗与关联
                         v
                    Hive / DWD
                         |
              Spark 聚合与特征工程
                    /          \
               Hive DWS      ML 训练/预测
                    \          /
                     Hive / ADS
                         |
                JSON 导出或 FastAPI
                         |
                 ECharts Web 大屏
```

课程项目优先采用 Hadoop 伪分布式或 3 节点虚拟机部署。若时间有限，Kafka 可列为增强项，基础版使用 Python 定时增量采集即可，但 HDFS、Hive、Spark 至少应真实运行并保留任务日志和截图。

### 5.2 数据分层

| 层级 | 作用 | 建议数据表/目录 |
| --- | --- | --- |
| ODS | 原样保存采集数据，按日期和小时分区 | `ods_order`、`ods_pile_status`、`ods_station`、`ods_weather`、`ods_fault_event` |
| DWD | 清洗、去重、统一时间和状态编码 | `dwd_charge_order`、`dwd_pile_telemetry`、`dwd_fault_event`、`dwd_user_behavior` |
| DWS | 面向主题聚合和模型特征 | `dws_station_hourly`、`dws_pile_health_daily`、`dws_user_charge_profile` |
| ADS | 直接服务大屏和接口 | `ads_operation_overview`、`ads_load_forecast`、`ads_charge_time_prediction`、`ads_fault_risk`、`ads_station_recommendation` |

HDFS 路径统一按 `dt=yyyy-MM-dd/hour=HH` 分区，所有任务记录 `batch_id`、`source_time`、`process_time`，便于演示数据追溯。

### 5.3 数据采集

- 业务数据：只读 SQLite，按 `id` 或更新时间增量抽取订单、站点、电桩、用户、预约、费率。
- 设备数据：新增独立模拟器，每 5-10 秒生成电压、电流、功率、枪温、SOC、在线状态和错误码，不修改原业务逻辑。
- 环境数据：答辩稳定版使用预置天气和法定节假日 CSV；联网 API 作为可选项。
- 故障标签：基于温度过高、电压异常、通信中断、启动失败等规则生成带标签样本，用于课程模型训练和验证。

### 5.4 批处理与刷新频率

| 任务 | 建议频率 | 输出 |
| --- | --- | --- |
| 实时指标采集 | 5-10 秒 | Web 实时 KPI、事件流 |
| 小时级数据清洗与聚合 | 5 分钟或手动触发 | 站点小时特征 |
| 负荷推理 | 每 5 分钟 | 未来 1/6/24 小时预测 |
| 故障风险推理 | 每 5 分钟 | 每桩风险分和诊断标签 |
| 模型训练 | 每日或答辩前手动触发 | 模型文件、评估指标、版本 |

## 6. 机器学习模型具体方案

### 6.1 充电负荷预测

- 模型：基线模型使用历史同期均值；正式模型使用 Spark ML `GBTRegressor`，可选增加 Python LightGBM 进行对比。
- 粒度：`station_id + hour`，全网预测由各站点结果汇总。
- 特征：小时、星期、是否周末、是否节假日、温度、天气、前 1/6/24/168 小时负荷、7 日滚动均值、站点桩数、当前可用率、价格时段。
- 标签：下一小时充电量或平均功率。
- 输出：1/6/24 小时负荷、预计空闲桩数、高峰时段、P10/P50/P90 区间。
- 评价：MAE、RMSE、MAPE；与历史均值基线对比，展示误差改善率。

### 6.2 充电时长预测

- 模型：Spark ML `GBTRegressor` 或 `RandomForestRegressor`。
- 特征：目标电量、起始 SOC、电池容量、车型、电桩额定功率、环境温度、站点负载、历史同车型平均时长。
- 标签：订单实际持续分钟数。
- 输出：预计分钟数、完成时间、置信区间。
- 数据不足时：使用 `所需电量 / 有效功率` 的物理公式作为基线，并明确标记“规则估算”。

### 6.3 故障诊断

- 模型：`RandomForestClassifier`，类别为正常、过温、过压/欠压、通信异常、枪线异常。
- 特征：电压、电流、功率、枪温、离线时长、近 24 小时启动失败次数、历史故障次数。
- 输出：故障类别、风险概率、影响因素、运维建议。
- 评价：Precision、Recall、F1、混淆矩阵。高风险设备更关注 Recall，减少漏报。

### 6.4 异常风控

- 模型：Isolation Forest 或基于统计分位数的异常检测。
- 特征：单用户日充电次数、订单电量、金额、持续时间、失败频率、异地短时连续行为。
- 输出：风险分、异常类型、审核建议，不自动采取处罚动作。

### 6.5 智能推荐评分

使用可解释的综合评分，比直接训练黑盒模型更适合课程展示：

```text
推荐分 = 35% × 预测空闲率
       + 25% × 距离得分
       + 20% × 低价得分
       + 10% × 设备健康度
       + 10% × 充电速度得分
```

权重可在 What-if 模拟器中调整，推荐结果必须展示评分构成。

## 8. 数据接口约定

建议保留 `/data.json`，新增以下只读接口或静态 JSON：

| 地址 | 用途 |
| --- | --- |
| `/api/dashboard/overview` | KPI、设备状态、站点排行、事件流 |
| `/api/ml/load-forecast?stationId=&horizon=24` | 负荷与空闲桩预测 |
| `/api/ml/charge-time?...` | 充电时间预测 |
| `/api/ml/fault-risk?limit=10` | 高风险设备和诊断结果 |
| `/api/ml/recommendation?...` | 智能站点推荐 |
| `/api/bigdata/health` | Hadoop 任务、数据量、延迟和质量 |

推荐统一响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "meta": {
    "generatedAt": "2026-09-12T10:00:00+08:00",
    "source": "hive_ads",
    "modelVersion": "load-gbt-v1"
  }
}
```

前端请求优先级：真实 API → Hadoop 导出的 JSON → 现有 `/data.json` → 本地 mock。页面必须显示当前数据来源，不能把 mock 数据误标成实时数据。

## 10. 小组分工建议

以 5 人小组为例：

| 角色 | 主要任务 | 交付物 |
| --- | --- | --- |
| A：组长/架构与集成 | 接口契约、任务排期、联调、答辩串联 | 架构图、接口文档、集成版本 |
| B：Web 大屏 | 页面结构、ECharts、响应式、轮询与降级 | 四主题大屏、图表组件、前端测试 |
| C：Hadoop/数据工程 | HDFS、Hive 分层、Spark ETL、数据质量 | 建表 SQL、ETL 任务、运行截图 |
| D：机器学习 | 负荷与时长模型、评估、模型输出 | 模型、评估报告、预测 JSON |
| E：运维智能/测试 | 故障模型、模拟数据、验收与演示脚本 | 故障诊断、测试报告、演示数据 |

如果只有 4 人，可将 D、E 的风控模型降为增强项，由同一人先完成故障诊断。

## 11. 四阶段实施计划

### 第一阶段：大屏骨架与数据标准（2-3 天）

- 冻结指标口径、页面线框和 JSON Schema。
- 拆分当前单文件页面，完成四主题导航、KPI 和基础图表。
- 建立 mock 数据，确保前后端可以并行开发。

**验收：** 1920×1080 无滚动展示，1366×768 可正常缩放；断开后端仍能进入降级演示。

### 第二阶段：Hadoop 数据链路（3-5 天）

- 部署 HDFS、Hive、Spark。
- 实现 SQLite 增量抽取和遥测数据模拟。
- 完成 ODS、DWD、DWS、ADS 表与小时聚合任务。
- 输出运营总览和数据链路健康 JSON。

**验收：** 能从一条原始订单追溯到 ADS 指标；任务可重复执行且不会重复计数。

### 第三阶段：机器学习子系统（4-6 天）

- 先完成历史均值基线，再完成 GBT 负荷模型并对比误差。

### 第四阶段：亮点、联调与答辩（3-4 天）

- 完成 AI 决策建议、What-if、碳减排和数据质量面板。

**验收：** 单接口目标响应小于 500ms；大屏连续运行 30 分钟无明显内存增长或图表重建闪烁。

## 14. 答辩演示主线

1. 在用户端产生一笔充电订单，运营总览出现指标和事件变化。
2. 进入 AI 预测，选择站点，展示未来 1/6/24 小时负荷、空闲桩和高峰预警。
3. 输入车辆与目标电量，展示预计充电时长和完成时间。
4. 展示一个高温/离线模拟桩，查看风险概率、诊断原因和运维建议。
5. 调整 What-if 参数，观察增设电桩或调整电价后的拥堵与营收变化。
6. 打开大数据驾驶舱，说明数据如何经过 ODS、DWD、DWS、ADS 和模型后进入大屏。
7. 最后展示模型相对基线的误差改善、数据质量和服务降级能力。
